# Migrating to 8.0.0

## 1. Simplified API

Coding agents can follow [8.0.0.agents.md](8.0.0.agents.md), which lists
the same changes as mechanical rewrite rules.

| Previous options | Replacement |
| --- | --- |
| `defaultPinTheme`, `focusedPinTheme`, `submittedPinTheme`, `followingPinTheme`, `disabledPinTheme`, `errorPinTheme` | `theme: PinThemes(fallback: …, focused: …, submitted: …, following: …, disabled: …, error: …)` |
| `preFilledWidget: widget` | `PinTheme(placeholder: widget)` |
| `pinContentAlignment: alignment` | `PinTheme(alignment: alignment)` |
| `animationDuration`, `animationCurve` | `pinAnimation: PinAnimation.scale(duration: …, curve: …)` (every constructor accepts both) |
| `showCursor: false` | `cursor: const PinCursor.hidden()` |
| `showCursor: true`, `isCursorAnimationEnabled: false` | `cursor: const PinCursor.static()` |
| Default visible animated cursor | `cursor: const PinCursor.blinking()` (default) |
| Custom `cursor: widget` | `cursor: PinCursor.blinking(child: widget)` (or `static`) |
| `enabled: false` | `inputMode: PinInputMode.disabled` |
| `readOnly: true` | `inputMode: PinInputMode.readOnly` |
| `useNativeKeyboard: false` | `inputMode: PinInputMode.customKeyboard` |
| `obscureText: false` | `obscuring: null` (default) |
| `obscureText: true`, `obscuringCharacter: '*'` | `obscuring: const PinObscuring.character('*')` |
| `obscureText: true`, `obscuringWidget: widget` | `obscuring: PinObscuring.widget(widget)` |
| `pinAnimationType: PinAnimationType.slide`, `slideTransitionBeginOffset: offset` | `pinAnimation: PinAnimation.slide(beginOffset: offset)` |
| Other `PinAnimationType` values | Corresponding `PinAnimation.none/scale/fade/rotation()` constructor |
| `toolbarEnabled: false` | `enableInteractiveSelection: false` for no selection, or `contextMenuBuilder: null` for no modern menu |
| `mainAxisAlignment`, `crossAxisAlignment`, `separatorBuilder` | `layout: PinLayout(mainAxisAlignment: …, crossAxisAlignment: …, separatorBuilder: …)` |
| `keyboardType`, `textCapitalization`, `textInputAction`, `keyboardAppearance`, `enableSuggestions`, `autofillHints` | `keyboard: PinKeyboardConfig(keyboardType: …, textCapitalization: …, textInputAction: …, keyboardAppearance: …, enableSuggestions: …, autofillHints: …)` |
| `Pinput.builder(builder: …)` | `Pinput(itemBuilder: …)` |
| `PinItemStateType.initial` | Removed. Use `PinThemes(fallback: …)`. |
| `PinTheme.apply` | Removed. Use `copyWith`. |
| `PinThemes.resolveWith((state) => …)` | `PinThemes.resolveWith((item, validation) => … item.type …)` |
| `onClipboardFound`, `onAppPrivateCommand`, `enableIMEPersonalizedLearning` | Removed. Read the clipboard in your app; IME learning is always off. |
| `AndroidSmsAutofillMethod` | Removed. Use `smsRetriever` (see the 5.0.0 notes below). |

Things that behave differently, not only renamed:

- **Themes are not merged.** A state theme is used exactly as written, as before.
  Derive it from the base with `copyWith`. A state you leave out falls back to
  `fallback`, which defaults to `PinTheme.defaults`. `PinThemes.resolveWith((item, validation) => …)`
  and `PinThemes.all(theme)` follow the same rule.
- **Disabled never takes focus**, including with directional navigation.
- **One constructor.** `Pinput.builder(builder: …)` is now
  `Pinput(itemBuilder: …)`. With `itemBuilder`, `theme` and `cursor` are not
  used; only the `pinAnimation` duration and curve apply (they animate the error
  layout), and `obscuring` only enables native masking, so the builder masks
  visible content itself. The builder gets the same `autofillHints` and
  `enableInteractiveSelection` defaults as the default renderer.
- **`customKeyboard` is focusable** (focus traversal, accessibility,
  `requestFocus()`), but still ignores pointer input and never opens the native
  keyboard.
- **Validation styling.** `PinThemes(valid: …, validating: …)` styles the pins
  while the app supplies those validation states. Without them nothing changes.
- The default error message is announced as a live region. Content from a custom
  `errorBuilder` should add its own `Semantics(liveRegion: true)` if needed.

There is now one selection enablement policy: `enableInteractiveSelection`.
When omitted, each constructor retains its existing default and the default
constructor uses Flutter's effective selection policy. The removed toolbar flag
no longer independently gates selection gestures.
Legacy custom `selectionControls` that build toolbars can ignore
`contextMenuBuilder`, as in Flutter; use `TextSelectionHandleControls` for modern
handle customization.

## 2. App-owned validation

Pinput no longer runs validators or registers an internal Flutter `FormField`.
This is a breaking API change:

- Replace `validator` and `pinputAutovalidateMode` with checks in `onChanged`,
  `onCompleted`, `onSubmitted`, or a submit handler.
- Replace `errorText` and `forceErrorState` with
  `PinputValidationState.invalid(message)`. Use `invalid()` for error styling
  without default text, or provide text directly through `errorBuilder`.
- Use `idle()`, `validating()`, and `valid()` to represent other results.
  These states do not display feedback or affect input availability.
- `showErrorWhenFocused` is removed. Invalid feedback is always visible,
  including during focus and editing, until the app changes `validationState`.
- Clear stale validation results on edits and ignore outdated async responses.
  Completion callbacks still report input completion, not successful validation.
- Keep `errorTextStyle`, `errorBuilder`, and `errorPinTheme` for presentation.
  `errorBuilder` receives the optional message and the PIN, and runs for invalid
  states even when the message is null.
  Both constructors expose the error builder and text style.
- For native Form validation, wrap Pinput in `FormField<String>` and map its
  error to `validationState`. Synchronize controller changes and reset explicitly.
  See the README's Flutter Form integration examples.

```dart
Pinput(
  validationState: pinValidation,
  onChanged: (pin) {
    setState(() => pinValidation = const PinputValidationState.idle());
  },
  onCompleted: (pin) {
    setState(() {
      pinValidation = pin == '2222'
          ? const PinputValidationState.valid()
          : const PinputValidationState.invalid('Pin is incorrect');
    });
  },
)
```
