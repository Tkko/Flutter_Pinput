# Pinput 8.0.0 migration rules for coding agents

Apply these rewrites to code that uses the `pinput` package, then run
`dart analyze` and fix what remains. Human-oriented notes: `8.0.0.md` in this folder.
Process every `Pinput(` and `Pinput.builder(` call site (`Pinput.builder(builder:` becomes `Pinput(itemBuilder:`, section 8). Do not rename
anything that is not a named argument of those constructors.

## 1. Themes

Collect the six theme arguments of one call into one `theme:` argument.

| Argument | Becomes |
| --- | --- |
| `defaultPinTheme: X` | `fallback: X` |
| `focusedPinTheme: X` | `focused: X` |
| `submittedPinTheme: X` | `submitted: X` |
| `followingPinTheme: X` | `following: X` |
| `disabledPinTheme: X` | `disabled: X` |
| `errorPinTheme: X` | `error: X` |

```dart
// before
Pinput(defaultPinTheme: base, focusedPinTheme: focused)
// after
Pinput(theme: PinThemes(fallback: base, focused: focused))
```

- Omit entries that were not set. Never pass `null` entries.
- State themes are NOT merged with `fallback`; each is used exactly as written.
  Keep existing `defaultPinTheme.copyWith(...)` expressions as they are, now
  against the `fallback` value.
- A single `defaultPinTheme` only: `theme: PinThemes.all(X)` or
  `theme: PinThemes(fallback: X)`.
- Do not use `PinThemes.fromMap`; it does not exist.

## 2. Pin content

- `preFilledWidget: W` -> put `placeholder: W` on every `PinTheme` of that call
  that should show it (usually `fallback`; `copyWith` carries it to derived
  themes).
- `pinContentAlignment: A` -> `alignment: A` on the `PinTheme`(s) of that call.

## 3. Animation

- Delete `animationDuration:` and `animationCurve:`. Move their values into
  `pinAnimation:` as `duration:` and `curve:`, keeping the existing animation
  constructor (default is `PinAnimation.scale`).
- With `itemBuilder`: `pinAnimation` is allowed; use `PinAnimation.none(duration:
  …, curve: …)` to configure the error layout animation only.

## 4. Cursor

| Before | After |
| --- | --- |
| `cursorBehavior: CursorBehavior.hidden` | `cursor: const PinCursor.hidden()` |
| `cursorBehavior: CursorBehavior.static` | `cursor: const PinCursor.static()` |
| `cursorBehavior: CursorBehavior.blinking` (or omitted) | `cursor: const PinCursor.blinking()` (or omit) |
| any of the above plus `cursor: W` | `cursor: PinCursor.<kind>(child: W)`; drop `const` |
| `cursor: W` only | `cursor: PinCursor.blinking(child: W)` |

Remove every reference to the `CursorBehavior` enum.

## 5. Input mode

| Before | After |
| --- | --- |
| `enabled: false` | `inputMode: PinInputMode.disabled` |
| `readOnly: true` | `inputMode: PinInputMode.readOnly` |
| `useNativeKeyboard: false` | `inputMode: PinInputMode.customKeyboard` |

If several were set on one call, use the strongest: `disabled`, then
`customKeyboard`, then `readOnly`. `enabled: true`, `readOnly: false` and
`useNativeKeyboard: true` are defaults; delete them. Replace reads such as
`pinput.enabled` with `pinput.inputMode`.

## 6. Removed arguments

Delete these and, where noted, replace the behavior in app code:

- `onClipboardFound` -> read `Clipboard.getData` in the app if needed.
- `onAppPrivateCommand`, `enableIMEPersonalizedLearning` -> delete.
- `AndroidSmsAutofillMethod` and related SMS enums -> use `smsRetriever`.
- Older removals: `validator`, `pinputAutovalidateMode`, `errorText`,
  `forceErrorState`, `showErrorWhenFocused` -> `validationState:` (see
  `8.0.0.md`); `showCursor`, `isCursorAnimationEnabled` -> section 4;
  `obscureText`, `obscuringCharacter`, `obscuringWidget` -> `obscuring:`;
  `pinAnimationType` -> `pinAnimation:`; `toolbarEnabled` ->
  `enableInteractiveSelection` / `contextMenuBuilder`.

## 7. Behavior changes to keep in mind

- Disabled inputs never take focus, in any navigation mode.
- The default invalid message is a live region; a custom `errorBuilder` is not
  wrapped, so add `Semantics(liveRegion: true)` yourself if announcements matter.
- A custom `itemBuilder` gets the same `autofillHints` and
  `enableInteractiveSelection` defaults as the default renderer.
- `customKeyboard` is focusable but still ignores pointer input.

## 8. Layout, keyboard and builder

| Before | After |
| --- | --- |
| `mainAxisAlignment: A`, `crossAxisAlignment: B`, `separatorBuilder: C` | `layout: PinLayout(mainAxisAlignment: A, crossAxisAlignment: B, separatorBuilder: C)` (only the ones that were set) |
| `keyboardType`, `textCapitalization`, `textInputAction`, `keyboardAppearance`, `enableSuggestions`, `autofillHints` | the same names as arguments of `keyboard: PinKeyboardConfig(...)` (only the ones that were set) |
| `Pinput.builder(builder: F, ...)` | `Pinput(itemBuilder: F, ...)` |
| `PinThemes.resolveWith((state) => … state …)` | `PinThemes.resolveWith((item, validation) => … item.type …)` |
| `PinItemStateType.initial` in a `switch` | delete the case; use `PinThemes(fallback: …)` |
| `PinTheme.apply(theme: t)` | delete; use `copyWith` |

## 9. Verify

1. `dart analyze` reports no removed-argument errors.
2. Search for leftovers: `rg "PinTheme:|cursorBehavior|CursorBehavior|animationDuration|animationCurve|preFilledWidget|pinContentAlignment|useNativeKeyboard|onClipboardFound|Pinput\.builder|PinItemStateType\.initial"`.
3. Run the project's tests.
